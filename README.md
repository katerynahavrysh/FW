# Каталог бібліотеки — деплой на Cloudflare Pages

У цій папці:
- `index.html` — сам сайт (каталог книг)
- `functions/api/storage.js` — маленький бекенд-роут, який Cloudflare Pages підхопить автоматично
- цей `README.md`

Дані (книги, оцінки, коментарі, PIN) зберігаються у **Cloudflare Workers KV** — це безкоштовне сховище ключ-значення від Cloudflare.

## Крок 1. Створити KV namespace

1. Зайдіть у [Cloudflare Dashboard](https://dash.cloudflare.com) → у лівому меню **Workers & Pages** → вкладка **KV**.
2. Натисніть **Create a namespace**.
3. Назвіть його, наприклад, `library-kv`, і створіть.

## Крок 2. Задеплоїти сайт

1. У **Workers & Pages** натисніть **Create application** → вкладка **Pages** → **Upload assets** (Direct Upload).
2. Дайте проєкту назву, наприклад `library-catalog`.
3. Перетягніть у вікно завантаження **всю цю папку** (з `index.html` і підпапкою `functions` всередині) — не окремі файли, а саму папку.
4. Натисніть **Deploy site**. За хвилину отримаєте посилання виду `https://library-catalog.pages.dev`.

## Крок 3. Прив'язати KV до проєкту

Це критичний крок — без нього збереження не працюватиме.

1. Відкрийте щойно створений Pages-проєкт → **Settings** → **Functions** → розділ **KV namespace bindings**.
2. Натисніть **Add binding**:
   - **Variable name**: `LIBRARY_KV` (рівно так, великими літерами — код очікує саме цю назву)
   - **KV namespace**: оберіть той, що створили в Кроці 1 (`library-kv`)
3. Збережіть.
4. Зайдіть на вкладку **Deployments** і натисніть **Retry deployment** (або зробіть новий деплой) — прив'язка застосовується тільки для нових деплоїв.

## Крок 4. Перевірити

Відкрийте посилання на сайт, зайдіть у режим бібліотекарки (PIN за замовчуванням: `1234`), додайте книгу, оновіть сторінку — якщо книга залишилась, все працює.

## Що варто зробити одразу після деплою

- **Змініть PIN-код за замовчуванням** — подвійний клік на назву бібліотеки (в режимі бібліотекарки) або кнопка-шестерня відкриває налаштування.
- PIN — це простий бар'єр, а не повноцінна авторизація: будь-хто з PIN-кодом може редагувати каталог. Для невеликої спільноти цього зазвичай достатньо.
- Дані в KV публічні для всіх відвідувачів сайту (це і потрібно для публічного каталогу) — окремих акаунтів читачок немає.

## Якщо щось не зберігається

- Перевірте, що binding називається саме `LIBRARY_KV` (великими літерами, з підкресленням).
- Перевірте, що робили новий деплой/retry deployment після додавання binding — стара збірка про нього не знає.
- Відкрийте консоль розробника (F12) у браузері на сайті — там будуть видно помилки запитів до `/api/storage`.
